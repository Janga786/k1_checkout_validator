# Booster K1 Cart-Seek — Debug Report (static audit + fixes)

_Generated 2026-06-29. Audit: 116 agents, 36 candidate findings, **29 confirmed** (>=2/3 adversarial verifiers), 7 refuted._

## Decision: pivoted Nav2/SLAM → reactive visual-servo

The audit showed the Nav2 stack had **4 blockers + ~10 highs**, several structural (lifecycle never activated; the fixed camera TF desyncs from the panning head; the dry-run can't even exercise the head path). The chosen fix is a **reactive controller (`cart_approach`)** that turns the body to centre the cart and walks to the standoff using the body-relative camera bearing+range, with the head held forward. This eliminates the Nav2-lifecycle, goal-pipeline, map-TF, and head-desync bug classes outright. Driving still goes through `booster_bridge` (gated by `/start_walking`, hard-clamped).

## Fixes applied this session

- **Reactive controller** `cart_approach.py` (+ `seek_cart_reactive.launch.py`, `run_seek_cart_reactive.sh`): pure visual servo, head fixed forward, turn-first then walk, EMA + score-gate + range-jump reject + lost-target STOP. Pure control law unit-tested in `test/test_cart_approach.py` (6/6 closed-loop cases pass).
- **launch-1 (blocker, mine):** detector is now started AFTER `nav_cleanup` in the reactive runner, so hygiene can't SIGKILL it.
- **arrive-asymptote (found while testing):** added `arrive_tol` band + `min_approach` floor so the approach latches 'arrived' and stops cleanly instead of creeping to a halt.
- **detection-1 (high):** `cart_locate` now rejects vertically-clipped bboxes for ranging (the 1-5 m jumps) and falls back to the last trusted range.
- **detection-2 (high):** layered score gating — `cart_locate` floor 0.20, `cart_approach` goal-grade 0.30 + EMA smoothing.
- **sdk-2 / launch-2 (high):** `nav_cleanup.sh` now graceful-stops a live bridge (`/estop` + SIGINT → `safe_stop()` keeps it STANDING) before any `kill -9`.
- **The original zombie root-cause:** `nav_cleanup.sh` (robust PID-based kill that can't self-kill the shell) clears the orphan graveyard that broke TF + Nav2; wired into both runners.

## Still open (carried into the reactive design or needing the real robot)

- **sdk-1 (high):** a blocking `Move()` RPC on the single executor thread can delay `/estop` ~1-2 s. Recommend a MultiThreadedExecutor / reentrant callback group for the stop topics. (Applies to the bridge regardless of approach.)
- **dryrun-4 (high):** no freshness check on real `B1OdometerStateSubscriber` — a dead odom publishes a frozen pose. `cart_approach` doesn't use odom, so it's de-risked for the reactive path, but worth adding a 'NO ODOM' guard before WALKING.
- **yaw_sign / turn direction:** the reactive turn convention is parameterized (`yaw_sign`, default -1). Verify on the real robot that it turns TOWARD the cart; flip if not.
- **head_pitch / real_height / hfov:** monocular range depends on these; validate on the real cart.

- **[high] Monocular range geometry ignores camera tilt + vertical bbox offset — cart_locate.py:128-135 (X,Y,Z in optical frame) consumed by qr_goal.py:70-71 (qx,qy taken as planar map coords) through the pitched static TF cam_tf rpy 0 0.175 0 (seek_cart.launch.py:67)** — cart_locate emits a full 3D optical point (X right, Y down, Z=range forward).
